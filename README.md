Pet Care Clinic Management System

1. Project Overview

The Pet Care Clinic Management System is a Java-based application developed using Spring Boot. It helps manage pet records, including pet name, species, age, and owner name.

The application provides REST APIs to create, retrieve, update, and delete pet records. It uses MySQL to store pet information and follows a layered architecture to separate responsibilities.

2. Technologies Used

- Java 21 – Programming language
- Spring Boot – Application framework
- Spring Web – Building REST APIs
- Spring Data JPA – Database access and repository operations
- Hibernate – Object-relational mapping (ORM)
- MySQL – Relational database
- Maven – Dependency management and build tool
- Jakarta Bean Validation – Validating pet details
- JUnit 5 – Unit testing
- Mockito – Mocking dependencies during testing
- IntelliJ IDEA – Development environment

3. Project Architecture

The application follows a layered architecture.

- Model: The "Pet" entity represents pet information stored in the database.
- Controller: "PetController" receives HTTP requests and returns API responses.
- Service: "PetService" contains the business logic for pet operations.
- Repository: "PetRepository" uses Spring Data JPA to interact with the database.
- Exception Handling: Handles missing pet records and invalid request data.

4. Database and Entity Description

The application uses a MySQL database named "petcareclinic" and a table named "pets".

The "Pet" entity contains the following fields:

Field| Data Type| Description
"id"| Long| Unique identifier generated automatically
"name"| String| Name of the pet
"species"| String| Type of pet, such as Dog or Cat
"age"| Integer| Age of the pet; must not be negative
"ownerName"| String| Name of the pet's owner

Each pet is stored as a separate record in the "pets" table. The "id" field is the primary key.

Database Configuration

Configure your MySQL connection in "src/main/resources/application.properties".

Example configuration:

spring.datasource.url=jdbc:mysql://localhost:3306/petcareclinic
spring.datasource.username=YOUR_MYSQL_USERNAME
spring.datasource.password=YOUR_MYSQL_PASSWORD
spring.jpa.hibernate.ddl-auto=update
spring.jpa.show-sql=true
spring.jpa.open-in-view=false

Replace the username and password placeholders with your local MySQL credentials.

Security note: Do not upload real database passwords to a public repository. For a published project, use environment variables or another secure configuration method.

5. How to Run the Project

1. Install Java 21 and MySQL.
2. Open the project in IntelliJ IDEA.
3. Ensure the "petcareclinic" database exists in MySQL.
4. Configure the database credentials in "application.properties".
5. Reload the Maven project and dependencies.
6. Run "PetCareClinicApplication.java".
7. Use IntelliJ IDEA's HTTP client and the "pet-api.http" file to test the APIs.

6. REST API Endpoints

All pet endpoints use the base path "/api/pets".

HTTP Method| Endpoint| Description
POST| "/api/pets"| Add a new pet
GET| "/api/pets"| Retrieve all pets
GET| "/api/pets/{id}"| Retrieve a pet by ID
PUT| "/api/pets/{id}"| Update an existing pet
DELETE| "/api/pets/{id}"| Delete a pet

Sample Request: Add a Pet

Send a "POST" request to "/api/pets" with the following JSON body:

{
"name": "Bruno",
"species": "Dog",
"age": 3,
"ownerName": "Rahul"
}

Sample Response

The response body may look like this:

{
"id": 1,
"name": "Bruno",
"species": "Dog",
"age": 3,
"ownerName": "Rahul"
}

The actual ID is generated by the database and may differ.

7. Validation and Exception Handling

The application validates incoming pet details.

- Pet name is required and cannot exceed 100 characters.
- Species is required and cannot exceed 50 characters.
- Age is required and cannot be negative.
- Owner name is required and cannot exceed 100 characters.
- If a requested pet ID does not exist, the application throws "PetNotFoundException".
- "GlobalExceptionHandler" converts supported exceptions into appropriate HTTP error responses.

8. HTTP Response Codes

Status Code| Meaning| Example
"200 OK"| Request completed successfully| Retrieving or updating a pet
"201 Created"| A new pet was created| Adding a pet, if the controller returns this status
"204 No Content"| Request succeeded with no response body| Deleting a pet
"400 Bad Request"| Request data failed validation| Blank pet name or negative age
"404 Not Found"| Requested pet does not exist| Retrieving a pet using an unknown ID

The exact response status depends on the controller implementation. For example, a POST method that directly returns a pet object usually responds with "200 OK" unless it explicitly sets "201 Created".

9. Testing

The project includes unit tests for "PetService" using JUnit 5 and Mockito.

The tests verify that:

1. An existing pet is returned with the expected details.
2. "PetNotFoundException" is thrown when a requested pet ID does not exist.

Both service unit tests passed in IntelliJ IDEA, and the Maven test build completed successfully.

To run the tests using Maven, execute:

mvn test
Automatic Consultation Fee Calculator

The system automatically calculates the consultation fee based on the pet's species and age.

Sample Fee Rules

Pet Species| Base Fee
Dog| ₹500
Cat| ₹400
Bird| ₹300
Other species| ₹350

Age-Based Additional Fees

- Pets younger than 1 year: ₹100 additional fee.
- Pets aged 1–7 years: no additional fee.
- Pets older than 7 years: ₹150 additional fee.

Examples

- A 3-year-old dog: ₹500.
- A 10-year-old cat: ₹550.
- A bird aged 0 years: ₹400.

These are sample rates for this academic project, not actual veterinary clinic prices. The fee is calculated automatically and included in the API response; it is not stored as a separate database column.
